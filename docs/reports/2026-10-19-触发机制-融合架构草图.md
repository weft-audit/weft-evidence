# 带触发机制的对话者 × 多 Agent：融合架构草图（预研，未实现）

> 定位：自荐信与 README 中的未完成 Roadmap，不冒充现状。

## 状态机（文字版）

```
用户输入
   │
   ▼
[意图识别层 · 触发机制]
   │
   ├─ 未识别为工作意图 ──→ [对话者自由区]：闲聊应答，不拉任何工具
   │
   └─ 识别为工作意图 ──→ [确认闸]：向用户反问确认
         │
         ├─ 未确认 ──→ 回到自由区
         └─ 确认 ──→ [路由层]：按任务类型派给多 Agent 集团
                        │
                        ├─ 执行：办事者干活 / 审计者复查 / 记忆管家收工
                        └─ 结果回流 → [对话者] 以人话汇报
                              └─ 收工：五段式报告 + 三层记忆落盘
```

## 关键设计点

- 触发机制 = 输入先过意图识别，再决定「闲聊还是工作」；识别不到就绝不动工具。
- 确认闸 = 识别到工作意图后必须反问确认，确认才拉起多 Agent——守门人不越权。
- 路由层 = 按任务类型（执行/审计/记忆）派给对应工作者，与现有三层审计对齐。
- 自由区承诺：对话者免日常审（所有者裁定），经桥派活的越界抽查另设。
