# DSH 多 Agent 拓扑迁移实战记录（公开脱敏版）

> 历史说明：本文中的“沙箱”均指当时 DSH 的权限/规则层，不代表当前机器具备
> 虚拟化隔离；当前环境仍按“无可用沙箱”处理。

## 一句话

把内部多 Agent 体系的治理层机制（六件套）整体搬进 DSH 0.2.1-rc.2：
核心链路 3 小时 10 分钟（23:39→02:52）跑通并测试，当天完成审计、挂载、
桌面端装载与发布。

## 迁移路径（怎么把逻辑扒出来、再挂上去）

1. 抽象：只搬「可复用、与人格无关」的治理能力——哨兵、完成否定、判断清单、
   账本、断点、评分官；不搬任何私人内容。
2. 验证阶梯：隔离实例先验（loaded 日志 + dump-config 组合树）→ 线上挂载
   （停服前双备份 + 逐项验收 + 自动回滚预案）→ 桌面端复用同配置。
3. 连接：官方 ACP stdio 建桥，Codex 与 DSH 智能体直接派活；
   纪律经官方 agent-instructions 机制自动注入（全局 + 项目两层 AGENTS.md）。

## 兼容性问题清单（全部真实发生）

1. skill-filesystem 注入行缺 `name` 字段 → preflight 崩溃、技能被静默禁用；
   最小复现 + 一行修复，双环境验证（已备官方 issue 材料）。
2. 客户端 SDK 0.4.4 缺 session/resume（服务端支持、loadSession 被拒）→
   会话 id 保留、降级标注。
3. usage_update 通知与 SDK schema 不匹配（-32602）→ 容错吞掉、不污染主流程。
4. 服务端默认把工作区读写与命令放行、不触发审批请求 → 改以只读沙箱为默认
   安全档，写操作经升级请求由客户端白名单裁决。
